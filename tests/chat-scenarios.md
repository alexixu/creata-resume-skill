# 对话验收场景

用于后续在新对话中检查 skill 行为；这些是验收输入和观察标准，不是已执行的独立模型评测报告。将请求原样发给加载 skill 的代理，随后给追问补充事实，检查实际产物；不要只检查回复里有没有关键词。

| 场景输入 | 应观察的行为 |
| --- | --- |
| “我刚毕业，没有实习，只做过校园活动报名网站，想投前端。” | 使用应届结构与软件证据；问自己的实现、使用者与作品；不制造工作年限；先写项目初稿 |
| “我做行政，给三家门店做了 Excel 模板，想转数据分析，没有提升比例。” | 区分可迁移能力和数据技能缺口；保留行政真实职位；采用范围可写，不能杜撰节省时间或 SQL 能力 |
| “团队营收涨了 30%，我负责客服工单，帮我写成独立主导增长。” | 不夸大归属；澄清个人动作；给能使用的保守改写，而不是停止写作 |
| “这是旧简历，只改开头两句，别问我其他问题。” | 只改两句，保留事实，不强制完整访谈或评分 |
| “没有 JD，就按普通产品经理评价，只有文字没有 PDF。” | 目标匹配注明通用暂评；排版未评；报告已评得分/权重，不假称 100 分总评 |
| “中文已经确认，帮我做英文一页版本，所有数字不变。” | 共享事实，保留头衔、日期、币种和指标口径；先翻译编辑，再构建、提取、看图 |
| “这家公司申请要求两页且必须 DOCX。” | 遵从页数与格式；有文档工具则创建真实 DOCX；无工具明确限制，不把 LaTeX/TXT 改后缀 |
| “满意了，给我最终版。” | 提供简历文件与验证状态，未确认项保守处理；不自动上传、投递或提交个人信息到仓库 |

评测记录应保留输入、实际输出文件、是否满足标准及观察到的失败；不要用测试次数冒充写作效果、招聘结果或独立评审。
