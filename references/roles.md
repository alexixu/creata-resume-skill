# 职业模板选择

实际可初始化的模板见 [role-templates.json](../assets/role-templates.json)。每个模板含章节顺序、证据追问和原创成果句骨架；空白字段供真实内容填充，不能把骨架当成用户经历。

| 模板 ID | 面向 | 应优先展示 |
| --- | --- | --- |
| software | 客户端、后端、前端、平台工程 | 交付范围、技术取舍、性能/可靠性与自己的实现 |
| data | 数据分析、算法、机器学习 | 数据口径、验证方法、基线、上线与离线的区别 |
| product | 产品经理 | 用户问题、优先级、实验、落地与归因 |
| design | UX/UI、交互、视觉 | 研究发现、设计决定、作品链接和验证 |
| marketing | 运营、市场、增长、内容 | 人群、渠道、漏斗、投入及真实业务结果 |
| sales | 销售、商务、客户成功 | 客群、周期、个人配额/成交/续费与团队归属 |
| finance | 财务、会计、审计 | 报表/控制/分析范围、准确性、资格和保密 |
| operations | 项目、供应链、行政、人力 | 流程、交付、质量、服务对象与协调范围 |
| graduate | 应届、实习、初次求职 | 教育、相关项目、实习/志愿，不硬造多年经验 |
| career-change | 转行、重返职场 | 目标定位、可迁移证据、相关项目和真实时间线 |

资深管理者在最相关职业模板中提升团队范围、资源选择和组织结果，明确个人决策；不要为了头衔自动增加预算、人数或战略职责。研究人员申请产业岗位可用 data 并增补精选论文；完整学术 CV 按用户要求另定结构。

职业可以组合：例如应届设计师以 graduate 的顺序、design 的作品证据来写。未覆盖的职业沿用最接近结构，依据实际 JD 创建章节，renderer 支持自定义章节，无需伪装成现有职业。

## 版式与内容分离

- `classic`：现有黑白分节线、姓名层级和 FontAwesome 分节图标，适合直接阅读的 PDF。
- `plain`：同样一栏和可读字体，取消装饰图标、联系方式逐行显示，面向机器抽取；仍需验证，不承诺 ATS 通过。

两种版式都不使用照片、技能进度条或双栏信息墙。用户要求设计变体时可以调整输出目录的样式，但保持文字可选择和阅读顺序。作品集用可读链接表达，不把简历做成作品集长图。
