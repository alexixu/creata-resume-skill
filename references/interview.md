# 访谈与写作

## 在聊天中推进

开场例：“你准备投什么岗位，面向哪里？可以直接贴旧简历或 JD；没有也没关系，我们从你最近做成的一件事开始。”已有资料则先归纳已知信息，不照读开场。

每轮结构：复述新确认的事实 → 写出 1–3 条简历句 → 简要解释取舍 → 只追问能改变下一版的缺口。用户回答“不知道”时换具体场景，不追着要数字。

### 找到证据

| 缺口 | 有用追问 | 可以形成的证据 |
| --- | --- | --- |
| 只有职责 | 最近一次最难的交付是什么？原来哪里卡住？ | 问题、约束、交付范围 |
| “我们做了” | 哪部分是你决定或实现的？哪些是同事负责？ | 个人动作与团队归属 |
| 没有增长数字 | 谁用了成果？交付/上线了吗？有验收或反馈吗？ | 采用情况、流程、质量、交付物 |
| 有百分比 | 从多少到多少？何时、什么样本？如何计算？ | 可解释指标及归因边界 |
| 资历短 | 课程、志愿、社团、实习中有真实使用者或作品吗？ | 应届生的真实成果 |
| 经历很多 | 哪三件最能证明目标岗位要求？ | 精选代表成果 |
| 空窗/转行 | 希望公开哪些经历？期间有没有相关学习或项目？ | 经用户认可的时间线，不制造雇佣关系 |

事实账本示例（虚构教学数据）：

```text
E01 | 用户本轮：每周整理门店报表，做了 Excel 模板，三个店在用
职责：自行设计模板；同事填写
行动：统一字段与异常提示
结果：三家门店采用；耗时变化未知
时间：待确认；状态：动作/范围用户确认，效率增幅待确认
```

可用草稿：“设计统一字段与异常提示的 Excel 报表模板，供三家门店每周汇总使用。”
不可用：“主导企业数字化转型，效率提升 80%。”

## 成果句与信息取舍

无方向或转行时，可将两三段真实经历分别映射到“与人协作、处理信息、制作或操作”的实际动作，找出重复出现的能力证据；同时问哪些任务愿意继续做。这个轻量做法受《What Color Is Your Parachute?》公开配套材料启发，见 [来源](sources.md)。不要强制用户完成原书整套练习，也不要将偏好当成熟练度。可以形成 `经历 → 已用能力 → 目标岗位需要 → 仍缺证据` 的四列对照。

常用骨架是“做了什么 + 用什么判断或方法 + 对谁产生什么已知结果”。只保留支持目标岗位的细节；不要每句机械塞满背景、任务、行动、结果四部分。

- 已测量：“重构图片缓存与请求合并逻辑，在同一设备测试集上将首屏中位耗时从 1.8 秒降至 1.2 秒。”仅在这些事实已确认时使用。
- 未量化：“建立发布回滚清单与告警责任表，纳入团队每周发布流程。”采用比无依据的“显著提升稳定性”更明确。
- 团队归属：“参与支付系统迁移，负责退款接口兼容与回归验证；项目按计划切换。”不把项目总收益全记到个人名下。

摘要从最强的两三条经历归纳，最后写，不用“积极上进，吃苦耐劳”。技能需在经历/项目或可信资格中有支撑，避免星级和自打分进度条。教育、奖项和证书保留真实名称与状态（在读、已完成、有效期等）。

## 多语言

中英文共享事实，不逐词直译。中文避免套话；英文使用具体动作，过去经历用过去时，当前持续职责用合适时态。职称不自动升级，学校/公司英文名优先用用户提供的官方名称，否则注明待核实。单位、币种、日期和数字口径保持一致。

用户纠正数字或贡献归属时，先更新原事实 ID，记录哪一轮取代了旧说法，再检查引用它的正文、摘要、JD 映射和评分理由。向用户展示修正后的句子，不再次追问已明确的信息。多版本需要文件同步时用 [版本工具](versions.md)；旧稿明确标为过期，不能只修当前聊天里的一句话。

## 岗位选材

用短表记录 `JD 要求 | 必须/优先/职责 | 事实 ID | 当前句子/章节 | 覆盖状态 | 缺口`。覆盖表示已有具体证据，部分覆盖表示只支持要求的一部分，缺口表示尚无可写证据。每个版本优先保留对应核心要求的成果，删弱相关和重复内容；时间线及正式职位名仍保持真实。

例如同一份门店报表经历，数据岗位可突出字段定义、异常检查及数据整理，运营岗位可突出使用者、协作流程和交付采用。不能据此补出 SQL、管理权限或效率百分比。把两个版本实际保留和省略的证据告诉用户，而不是只换目标岗位名称。

## 结束一轮

有完整初稿就贴出来或给文件，不再只输出写作课。将影响投递的未确认信息单独列出；用户不便补充时保守改写或省略。可按需从同一事实账本生成自我介绍、作品集简介、求职信和面试故事，不自动扩大交付范围。
